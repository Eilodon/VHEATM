# V17 P0 Hardening Implementation Plan

**Goal:** Close the four assurance gaps identified in the approved VHEATM V17 roadmap before capability-pack migration.

**Source:** User-provided VHEATM V17 Ultimate roadmap (`Hardened deterministic kernel + typed audit runtime + capability packs + evaluation flywheel`).

**Scope for this slice:**

1. Recompute activation from canonical manifest and context at every routing/report trust boundary.
2. Preserve taint and provenance lifecycle; raw artifact parsing must not clear taint.
3. Add shared typed artifact, module-run, module-result, failure-result, and validation-receipt contracts.
4. Derive gate results from validated module runs and typed outputs; reject caller-supplied passing claims.
5. Add the minimum context-v2 adapter and immutable parent-bound plan revisions so late findings can activate new obligations.

**Out of scope for this slice:** SQLite/CAS persistence, sandbox enforcement adapters, independent judge process, analyzer providers, and legacy capability migration. Those depend on the contracts established here.

## Verification gates

- `.venv/bin/vheatm-validate --root .`
- `.venv/bin/pytest`
- `.venv/bin/vheatm-evaluate --root . --context examples/context-low-risk.yaml`
- `.venv/bin/vheatm-route --root . --context examples/context-low-risk.yaml`
- Mutation tests for plan activation, tainted evidence, missing invocation, forged outputs, and unrelated evidence.

## Execution rule

Each behavior change follows RED → GREEN → REFACTOR. Schema and registry changes are canonical; no derived count or digest is hand-edited without regeneration and validation.
